Nov 5, 2026 · @Dongjin Kim

## 1. 프로젝트 개요

### 1.1 문제 정의

브라우저, 소셜 미디어, 지식 관리 서비스는 저장은 쉽게 만들었지만 저장 이후의 경험은 개선하지 않았다. 사용자는 수백\~수천 개의 자료를 저장하지만 다시 보지 않거나 필요할 때 찾지 못한다.

**문제 A. 저장한 콘텐츠를 다시 보지 않는다.**

- 나중에 읽으려고 저장하지만 잊어버린다.
- 새 콘텐츠를 계속 저장하면서 기존 자료가 묻힌다.
- 저장된 자료가 너무 많아 무엇부터 확인할지 모른다.
- 정리하는 것 자체가 부담스럽다.

**문제 B. 저장한 콘텐츠를 다시 찾지 못한다.**

- 제목이나 저장한 플랫폼을 기억하지 못한다.
- 정확한 키워드를 몰라 검색하기 어렵다.
- 결국 Google에서 다시 검색한다.
- 콘텐츠가 여러 플랫폼에 흩어져 있다.

### 1.2 제품 비전

> 저장한 콘텐츠를 잊지 않도록 다시 보여주고, 필요한 순간 빠르게 찾아준다.

여러 플랫폼에서 저장한 콘텐츠를 한곳에 모으고, AI가 내용을 이해하기 쉽게 정리한 뒤, 적절한 시점에 다시 보여주거나 검색 의도에 맞는 자료를 찾아준다.

### 1.3 핵심 가치

| 핵심 가치 | 설명 |
| --- | --- |
| Rediscover — 재발견 | 잊고 있던 콘텐츠를 주기적으로 다시 보여주기. 제품의 wedge |
| Retrieve — 검색 | 제목이나 키워드를 기억하지 못해도 내용으로 찾기 |
| Save — 수집 | 어디에서든 클릭 몇 번으로 저장, 저장 시점에 본문까지 확보 |
| Understand — 이해 | AI 요약으로 원문을 열지 않고도 내용을 빠르게 파악하고, 보관할지 버릴지 바로 결정 |
| Organize — 관리 | 요약을 보고 내린 결정대로 중요한 콘텐츠는 보관하고 불필요한 자료는 제거 |

### 1.4 포지셔닝과 경쟁 제품

Rebomi의 wedge는 재노출이다. 요약과 의미 검색은 이미 여러 제품이 제공하므로 그것만으로는 갈아탈 이유가 되지 않는다. "저장한 것을 잊지 않게 해주는 서비스"로 포지셔닝하고, 검색과 요약은 그 약속을 지키기 위한 기반 기능으로 둔다.

| 제품 | 수집 | AI 요약 | 의미 검색 | 재노출 | 비고 |
| --- | --- | --- | --- | --- | --- |
| Pocket | 확장·모바일 | 없음 | 없음 | 없음 | 2025년 7월 서비스 종료. 이탈 사용자가 1차 타깃 |
| Raindrop.io | 확장·모바일 | 없음 | 제한적 | 없음 | 폴더·태그 중심의 정리 도구 |
| mymind | 확장·모바일 | 자동 태깅 | 있음 | 없음 | 정리 없이 저장하는 철학, 유료 |
| Readwise Reader | 확장·모바일 | 있음 | 제한적 | 하이라이트만 | 읽기 앱. 저장물이 아니라 하이라이트를 복습시킴 |
| Recall | 확장·모바일 | 있음 | 있음 | 복습 카드 | 지식 그래프 중심, 간격 반복 복습 |
| Rebomi | 확장·모바일·가져오기 | 있음 | 하이브리드 | 핵심 | 읽기를 강요하지 않는 재노출, 북마크 대량 가져오기 |

경쟁 제품 정보는 2026년 11월 기준 공개 자료에 근거한 요약이며, 출시 전 재확인이 필요하다. Readwise와 Recall의 복습은 "읽은 것의 암기"에 가깝고, Rebomi는 "읽지 않은 것의 재발견"을 다룬다는 점이 핵심 차이다.

## 2. 타깃 사용자

### 2.1 주요 타깃

온라인에서 콘텐츠를 자주 저장하지만 다시 확인하거나 검색하는 데 어려움을 겪는 개인 사용자(B2C).

- 브라우저에 수백\~수천 개의 북마크를 쌓아둔 사람
- Reddit, YouTube, X 등에서 유용한 자료를 자주 저장하는 사람
- 공부하거나 새로운 분야를 탐색하면서 자료를 모으는 사람
- 과거에 저장한 글을 기억하지 못해 반복 검색하는 사람
- Pocket 종료 이후 대체 서비스를 찾지 못한 사람

### 2.2 핵심 사용자 시나리오

**시나리오 A — 재발견**

1. 사용자가 Reddit 앱에서 게시물을 공유 메뉴로 저장한다. 공유창이 게시물 본문을 함께 전송한다.
2. 서비스가 자동으로 내용을 요약한다.
3. 일주일 뒤 홈 화면에 해당 자료를 다시 보여준다.
4. 사용자가 요약을 확인하고 원문을 다시 읽는다.
5. 유용한 자료는 보관하고 필요 없는 자료는 삭제한다.

**시나리오 B — 검색**

1. 과거에 저장한 기술 관련 자료가 필요해진다.
2. 제목이나 출처는 기억하지 못한다.
3. "Next.js에서 여러 서비스를 독립적으로 배포하는 방법에 관한 글"이라고 검색한다.
4. 서비스가 검색어와 의미적으로 관련된 자료를 보여준다.
5. 요약을 보고 원하는 자료를 찾아 원문을 연다.

**시나리오 C — 기존 북마크 정리**

1. Chrome에서 북마크 1,300개를 가져온다.
2. 서비스가 제목, URL, 접근 가능한 본문을 수집하고 죽은 링크는 별도로 표시한다.
3. AI가 각 콘텐츠의 요약을 생성한다.
4. 가져온 북마크는 재노출 피드에 바로 나오지 않는다. 사용자가 폴더 단위로 재노출에 포함할 것을 고른다.
5. 검색하거나 목록을 탐색하면서 필요한 자료를 찾고, 죽은 링크와 오래된 자료를 일괄 정리한다.

## 3. 플랫폼 구성

네 클라이언트 모두 P0이며, 공통 원칙은 "저장하는 쪽이 본문도 함께 보낸다"이다.

### 3.1 웹 애플리케이션 (P0)

콘텐츠 관리, 검색, 재노출, 설정, 북마크 가져오기를 제공하는 메인 플랫폼. **기술:** Next.js

### 3.2 브라우저 확장 프로그램 (P0)

Chrome을 우선 지원한다.

- 현재 페이지 원클릭 저장
- 저장 시점에 렌더링된 DOM에서 본문·제목·대표 이미지를 추출해 서버로 전송 (Readability 계열 라이브러리)
- 로그인 상태의 페이지, 페이월 뒤 페이지, SNS 게시물도 사용자가 보고 있는 그대로 캡처
- 저장 성공·중복 여부 즉시 표시
- 사용자 계정과 동기화

다른 Chromium 기반 브라우저와 Firefox는 추후 검토한다.

### 3.3 모바일 애플리케이션 (P0)

**기술:** React Native + Expo. 지원 플랫폼: iOS, Android.

사용자가 다른 앱에서 공유 버튼을 눌러 서비스를 선택하면, 메인 앱으로 전환하지 않고 공유창에서 즉시 저장할 수 있어야 한다.

- iOS: Share Extension 기반 저장 UI. Safari에서 공유하면 페이지 본문(JavaScript preprocessing)도 함께 수신
- Android: Share Intent 기반 저장 전용 UI. 공유된 텍스트·URL을 수신, 본문은 서버 보조 추출
- 저장 후 원래 앱으로 복귀
- AI 요약은 저장 이후 서버에서 비동기 처리
- 공유 확장은 메인 앱과 로그인 세션을 공유(iOS App Group, Android 공유 저장소)

UI 형태는 운영체제 제약에 따라 다를 수 있지만 사용자 경험은 최대한 일치시킨다. PWA는 MVP 필수 플랫폼에서 제외한다.

## 4. 핵심 기능 요구사항

### 4.1 콘텐츠 수집

**우선순위: P0**

사용자는 다양한 플랫폼에서 콘텐츠를 하나의 저장소로 수집할 수 있어야 하며, 저장 시점에 본문까지 확보하는 것을 기본으로 한다.

**기능 요구사항**

- 브라우저 확장 프로그램, 모바일 공유 메뉴, 웹 URL 입력을 통한 저장
- 제목, URL, 도메인, 대표 이미지, 저장일 수집
- 중복 URL 감지 (정규화된 URL 기준, 트래킹 파라미터 제거)
- 사용자 계정 기준 기기 간 동기화
- 저장 후 비동기 AI 처리, 실패 시 재시도

**본문 추출 전략**

타깃 사용자의 주요 출처(Reddit, YouTube, X, Instagram)는 서버 측 추출이 가장 어려운 곳이다. 따라서 추출의 1순위는 클라이언트다.

| 순위 | 방식 | 적용 | 강점 |
| --- | --- | --- | --- |
| 1 | 클라이언트 캡처 | Chrome 확장, iOS Safari 공유 | 로그인·페이월·SNS 페이지를 사용자가 보는 그대로 확보 |
| 2 | 공유 텍스트 | 모바일 앱 공유 (Reddit, X 앱 등) | 앱이 넘겨주는 제목·본문 일부 확보 |
| 3 | 서버 fetch | 웹 URL 입력, 북마크 가져오기, 1·2 실패 시 | 공개 페이지·블로그·뉴스에 충분 |
| 4 | 메타데이터만 | 1\~3 모두 실패 | 제목·OG 설명·도메인으로 검색 가능 |

콘텐츠마다 추출 수준(본문 / 일부 / 메타데이터만)을 저장하고 화면에 표시한다. YouTube는 자막 API 접근 가능 시 자막을 본문으로 쓰고, 불가 시 제목·설명으로 처리한다.

**지원 콘텐츠:** 일반 웹페이지, 블로그·뉴스 기사, Reddit 게시물, YouTube 동영상, X·Instagram 등 SNS 링크.

#### 기존 북마크 가져오기 (P0)

- Chrome 북마크 HTML 파일 가져오기, 다수 URL 일괄 등록
- 폴더명을 "가져온 폴더" 속성으로 보존. 보관함 필터와 재노출 포함 여부(4.4)에 사용
- 중복 제거, 진행 상태 표시
- 대량 등록 시 순차적 메타데이터 수집 및 요약 (우선순위: 최근 북마크부터)
- 응답 없음·404·도메인 소멸 링크는 **링크 소멸** 상태로 분류. 요약·임베딩을 생략해 비용을 아끼고, 정리 화면에서 일괄 삭제를 제안
- 가져온 콘텐츠는 재노출 대상에서 기본 제외

본문이나 요약이 준비되지 않아도 가져온 북마크는 즉시 목록과 키워드 검색에 나타나야 한다.

### 4.2 콘텐츠 자동 요약

**우선순위: P0**

- 추출된 본문을 바탕으로 1\~3문장 요약
- 원본 제목, 출처, 이미지 표시
- 사용자 언어에 맞는 요약 (한국어·영어)
- 요약 생성 중, 완료, 실패, 본문 없음 상태 구분
- 메타데이터만 있는 콘텐츠는 OG 설명을 요약 자리에 표시

요약은 사용자가 콘텐츠의 주제와 유용성을 판단할 수 있도록 구성한다.

**P1:** 핵심 포인트 추출, 요약 재생성, 여러 요약 길이, YouTube 자막 기반 상세 요약.

### 4.3 지능형 검색

**우선순위: P0**

제목이나 정확한 키워드를 기억하지 못해도 저장한 콘텐츠를 찾을 수 있어야 한다.

**검색 유형**

1. 키워드 검색: 제목, URL·도메인, AI 요약, 사용자 메모, 추출된 본문
2. 의미 기반 검색: 자연어 검색 의도와 내용이 비슷한 자료. 예: "스마트폰 중독을 줄이려고 앱을 잠그는 방법" → 앱 사용 제한, 스크린타임, 디지털 디톡스 자료
3. 하이브리드 검색: 두 결과를 RRF로 결합

**검색 결과 화면:** 제목, 요약, 출처, 저장일, 매칭 근거(일치 키워드 또는 관련 문장), 추출 수준, 원문 열기, 보관/삭제.

**검색 요구사항**

- 자연어 문장 검색, 한국어·영어 혼합 콘텐츠 검색
- 의미적으로 관련된 자료 우선, 정확한 키워드 일치 자료도 적절히 상위 표시
- 요약 생성 전 자료도 제목·URL로 검색 가능
- 결과 없음 시 명확한 안내

**MVP에서 제외:** 저장 문서 AI 챗봇 질의응답, 여러 문서를 종합한 AI 답변, 외부 웹 검색 통합. 검색의 MVP 목표는 AI가 답을 생성하는 것이 아니라 저장한 원본을 정확히 찾아주는 것이다.

### 4.4 주기적 재노출

**우선순위: P0 — 제품의 핵심 차별점**

저장된 콘텐츠를 다시 확인하고 활용할 기회를 제공한다. 읽기를 강요하지 않고, 사용자가 잊은 것을 떠올리게 하는 데 집중한다.

**기본 동작**

- 저장된 콘텐츠 중 일부를 일정 주기로 선정해 홈 화면에 표시
- 사용자별 재노출 빈도 설정
- 최근 확인한 자료는 반복하지 않음
- 재노출 자료를 처리할 수 있는 액션 제공

**재노출 대상 풀**

재노출 대상 여부는 보관 상태와 별도로 관리한다.

| 콘텐츠 출처 | 기본값 | 변경 방법 |
| --- | --- | --- |
| 확장·모바일·웹에서 직접 저장 | 포함 | 콘텐츠별 "재노출 중단" |
| 북마크 가져오기 | 제외 | 가져온 폴더 단위로 포함, 또는 콘텐츠별 포함 |
| 보관됨 | 설정에 따름 (기본 포함) | 설정에서 끄기 |
| 링크 소멸 | 제외 | 변경 불가 |

가져온 북마크를 기본 제외하는 이유: 1,300개를 가져온 직후 "오래된 자료 우선" 규칙을 그대로 적용하면 몇 달간 피드가 과거의 저품질 북마크로 채워져 재노출 피로도(11.4)의 가장 큰 원인이 된다.

**선정 기준 (규칙 기반)**

- 저장한 지 7일 이상 지났는가
- 이전 재노출 이후 14일 이상 지났는가
- 최근 7일 내 사용자가 확인하지 않았는가
- 삭제·재노출 중단·링크 소멸이 아닌가
- 같은 회차에 같은 도메인이 2개를 넘지 않는가

**초기 기본 설정:** 주 2\~3회, 회당 3\~5개, 홈 화면 표시, 동의한 경우 모바일 푸시 알림.

**콘텐츠별 액션:** 원문 열기, 나중에 다시 보기, 보관하기, 재노출 중단, 삭제하기. 원문을 열었다는 이유만으로 읽기를 완료했다고 단정하지 않는다.

**P1:** 관심사 기반 재노출, 검색 주제 관련 자료 재노출, 주간 이메일 다이제스트, 재노출 날짜 직접 지정, 행동 기반 추천 최적화.

### 4.5 콘텐츠 관리

**우선순위: P0**

- 전체 콘텐츠 목록, 검색 및 정렬
- 보관, 삭제, 삭제 복구, 일괄 처리
- 저장일·출처·추출 수준 확인
- 한 줄 메모 (검색 대상에 포함)
- 가져온 폴더별 필터
- 정리 화면: 링크 소멸 콘텐츠 일괄 삭제 제안

**콘텐츠 상태**

| 상태 | 설명 |
| --- | --- |
| Inbox | 새로 저장한 콘텐츠. 30일이 지나면 자동으로 보관됨으로 이동 |
| 보관됨 | 사용자가 유지하기로 했거나 30일이 지난 콘텐츠 |
| 휴지통 | 삭제한 콘텐츠. 30일 후 영구 삭제 |
| 링크 소멸 | 원문에 접근할 수 없는 콘텐츠. 어느 상태에나 겹쳐 붙는 플래그 |

Inbox 자동 보관은 "정리를 강요하지 않는다"는 원칙(14장)을 지키기 위한 장치다. 사용자가 Inbox를 비우지 않아도 쌓이지 않으며, 보관된 콘텐츠도 검색과 재노출 대상이 된다.

**P1:** 출처별 필터, 태그, 사용자 폴더, 중복·유사 콘텐츠 정리, 오래된 콘텐츠 일괄 정리 추천.

## 5. 핵심 화면 및 정보 구조

### 5.1 홈

서비스를 열었을 때 가장 먼저 보는 화면. 재노출이 제품의 중심이므로 첫 화면의 중심에 둔다.

1. 오늘의 재노출 콘텐츠 (3\~5개, 카드형, 액션 버튼 포함)
2. 상단 검색창 (항상 노출)
3. 최근 저장 콘텐츠

### 5.2 검색

자연어 검색 입력, 결과 목록, 결과별 요약과 매칭 근거, 원문 열기 및 관리.

### 5.3 Inbox

최근 30일 내 저장한 콘텐츠, 요약, 보관·나중에 보기·삭제, 일괄 관리.

### 5.4 보관함

전체 보유 콘텐츠, 최근순·오래된 순 정렬, 가져온 폴더별 필터, 선택 콘텐츠 관리.

### 5.5 정리

링크 소멸 콘텐츠, 중복 콘텐츠, 오래된 미확인 콘텐츠를 모아 일괄 삭제·보관을 제안하는 화면. 가져오기 직후 진입을 유도한다.

### 5.6 설정

계정 및 동기화, 재노출 주기, 재노출 대상(보관됨 포함 여부, 가져온 폴더 선택), 푸시 알림, 북마크 가져오기, 데이터 내보내기 및 삭제, 요금제.

## 8. 기술 구성

### 클라이언트

| 플랫폼 | 기술 | 본문 추출 역할 |
| --- | --- | --- |
| 웹 | Next.js | 없음 (서버 fetch) |
| 모바일 | React Native + Expo | 공유 텍스트 전달 |
| Chrome 확장 | React + TypeScript + Readability | 렌더링된 DOM에서 본문 추출 후 전송 |
| iOS 공유 수신 | Share Extension + App Group | Safari 페이지 본문 수신 |
| Android 공유 수신 | Share Intent 기반 전용 UI | 공유된 텍스트·URL 수신 |

### 서버

- 공통 API 서버, PostgreSQL
- 백그라운드 작업 큐: 메타데이터 수집, 서버 보조 추출, 링크 생존 확인, 요약, 임베딩
- LLM 기반 요약 (저비용 모델, 본문 기준 입력 토큰 상한 설정)
- Embedding 생성 및 검색 인덱싱
- 주기적 재노출 스케줄러
- 모바일 푸시 알림 서비스
- 결제 (Stripe 또는 앱 내 결제)

### 검색 아키텍처

PostgreSQL 하나로 시작하되, 한국어 키워드 검색은 기본 FTS로는 불가능하므로 확장을 전제한다.

| 구성 | 선택 | 이유 |
| --- | --- | --- |
| 키워드 검색 | PGroonga (대안: pg\_bigm) | PostgreSQL 기본 FTS에는 한국어 사전이 없어 한국어 검색 품질이 매우 낮음. PGroonga는 한·영·일 혼합 전문 검색을 한 인덱스로 처리 |
| 의미 검색 | pgvector + bge-m3 (대안: multilingual-e5-large) | 한·영 혼합 쿼리와 문서에서 검증된 다국어 임베딩. 자체 호스팅 가능 |
| 결과 결합 | Reciprocal Rank Fusion (RRF) | 점수 스케일을 맞출 필요가 없어 단순하고 MVP에 충분 |
| 검색 대상 | 제목, 요약, 메모, 추출된 본문 (청크 단위 임베딩) | 긴 본문은 청크로 나누어 매칭 근거 문장을 제시 |

모델 선택은 Phase 2에서 실제 한국어·영어 혼합 쿼리 100개로 비교 평가한 뒤 확정한다. 대규모 검색 전용 인프라나 복잡한 RAG 아키텍처는 처음부터 도입하지 않는다.

## 9. 비즈니스 모델과 비용 한도

사용자 한 명이 1,300개를 가져오면 요약과 임베딩 비용이 즉시 발생하므로, 무료 한도는 MVP 단계에서 설계한다. 수치는 출시 전 실제 비용 측정 후 조정한다.

| 항목 | Free | Pro (월 구독) |
| --- | --- | --- |
| 저장 콘텐츠 수 | 500개 | 무제한 |
| 북마크 가져오기 | 최초 1회, 500개까지 | 무제한 |
| AI 요약·임베딩 | 월 300개 | 월 3,000개 |
| 재노출 | 홈 피드 | 홈 피드 + 푸시 + 이메일 다이제스트(P1) |
| 검색 | 전체 기능 | 전체 기능 |

**비용 통제 장치**

- 링크 소멸 콘텐츠는 요약·임베딩 생략
- 동일 URL은 사용자 간 요약·임베딩 캐시 공유 (공개 페이지에 한함)
- 본문 입력 토큰 상한 (예: 4,000 토큰)
- 대량 가져오기는 최근 북마크부터 순차 처리, 한도 초과분은 메타데이터만 등록

**목표 단위 경제:** Pro 사용자 1인당 월 AI 비용을 구독료의 15% 이하로 유지한다. 요약 1건당 비용과 임베딩 1건당 비용은 Phase 2에서 측정해 기록한다.

## 10. 성공 지표

### North Star Metric

**주간 활성 사용자 1인당 재활용 수**

절대값은 사용자 수에 비례해 커지므로 비율로 정의한다. "재활용"은 다음 중 하나로 센다.

- 재노출 카드에서 원문 열기, 보관하기, 나중에 다시 보기 중 하나를 실행
- 검색 결과에서 원문 열기
- 재노출 카드를 펼쳐 요약을 읽은 뒤 5초 이상 체류 (원문을 열지 않은 재발견도 가치가 있다는 원칙 반영)

삭제와 재노출 중단은 재활용으로 세지 않지만, 정리 성공으로 별도 집계한다.

### 재노출 지표 (wedge 검증)

- 재노출 콘텐츠 확인률 (카드 펼침 / 노출)
- 재노출 후 원문 열람률, 보관률, 삭제률
- 재노출 알림 해제율, 빈도 하향 조정률
- 재노출 피드를 주 1회 이상 확인한 사용자 비율

### 검색 지표

- 검색 실행 사용자 비율
- 검색 결과 클릭률, 검색 후 원문 재열람 비율
- 검색 실패율 (결과 없음 또는 클릭 없이 재검색)
- 첫 클릭까지 소요 시간

### 제품 전체 지표

- 주간 활성 사용자, 4주 유지율
- 사용자별 저장 콘텐츠 수, 본문 확보 비율
- 대량 가져오기 이용률, 가져오기 후 정리 화면 사용률
- Free → Pro 전환율

목표치는 Phase 2 사용자 테스트 후 설정한다.

| 11.1 본문 추출 제한 | 타깃 사용자의 주요 출처(Reddit, YouTube, X, Instagram)가 서버 추출이 가장 어려운 곳이라 핵심 콘텐츠에서 요약·의미 검색이 작동하지 않을 수 있음 | 클라이언트 캡처를 1순위로 두고(4.1), 추출 수준을 콘텐츠마다 표시. Reddit·X의 접근 정책 변화를 분기마다 점검 |
| 11.2 링크 소멸 | 오래된 북마크의 상당수가 404. 가져오기 직후 품질 체감 저하와 불필요한 AI 비용 | 가져오기 시 생존 확인, 링크 소멸 플래그, 요약 생략, 정리 화면에서 일괄 삭제 제안 |
| 11.3 의미 검색 정확도 | 임베딩만으로 모든 자료를 찾을 수 없음. 한국어 키워드 검색은 기본 FTS로 불가 | PGroonga + bge-m3 + RRF(8장). Phase 2에서 한·영 혼합 쿼리 100개로 평가 |
| 11.4 재노출 피로도 | 빈도가 높거나 관련성이 낮으면 알림을 끄거나 이탈 | 낮은 기본 빈도, 가져온 콘텐츠 기본 제외, 도메인 다양성 규칙, 한 번에 끌 수 있는 설정 |
| 11.5 AI 처리 비용 | 수천 개 가져오기 시 비용 급증 | 무료 한도, 캐시, 토큰 상한, 링크 소멸 생략(9장) |
| 11.6 모바일 공유 확장 안정성 | iOS Share Extension과 Android 공유 수신은 메인 앱과 다른 실행 환경, 메모리 제한, 세션 분리 | 로그인 세션 공유, 네트워크 오류, 저장 완료 확인, 공유창 종료 동작을 별도 검증. iOS 확장은 메모리 120MB 제한을 설계 전제로 둠 |
| 11.7 경쟁 제품의 재노출 추가 | mymind, Raindrop 등이 재노출 기능을 붙이면 wedge가 약해짐 | 대량 가져오기 + 정리 + 재노출을 묶은 "북마크 구조조정" 경험으로 차별화. 재노출 품질 데이터를 빨리 쌓음 |
| 11.8 개인정보와 데이터 소유권 | 북마크는 관심사·개인정보를 포함. 클라이언트 캡처는 로그인 페이지 본문까지 서버에 저장함 | 비공개 기본값, 사용자별 접근 제한, 외부 AI 처리 시 데이터 정책 명시, 캡처 전 "이 페이지 본문도 저장됩니다" 안내, 내보내기·삭제 지원, 저작권 고려 |

## 12. 장기 확장 방향 (P2)

MVP에서 수집, 검색, 재노출의 가치를 검증한 후 사용자 수요에 따라 확장한다.

### 12.1 오디오 요약 및 브리핑

저장한 콘텐츠를 읽지 않고 이동 중에 소비할 수 있도록 지원한다. 개별 콘텐츠 오디오 요약, 여러 콘텐츠를 결합한 브리핑, 주간 오디오 다이제스트, 재노출 콘텐츠 듣기, 기본 플레이어 기능을 검토한다. 단순 낭독보다 듣기 편한 설명형 오디오를 지향한다.

### 12.2 AI 지식 검색 챗봇

저장한 콘텐츠를 바탕으로 질문에 답변하고 관련 원문을 연결한다.

### 12.3 콘텐츠 간 자동 연결

주제나 내용이 비슷한 콘텐츠를 자동으로 연결하고 관련 자료를 추천한다.

### 12.4 지식 카드 및 학습 기능

저장한 콘텐츠에서 핵심 지식을 추출해 복습 카드나 퀴즈를 생성한다.

### 12.5 지식 그래프

저장된 콘텐츠와 주제 사이의 관계를 시각화한다.

## 13. MVP 검증 가설

| 가설 | 내용 | 검증 시점 | 판단 지표 |
| --- | --- | --- | --- |
| H1 — 검색 | 자연어 검색으로 기존 북마크 검색보다 원하는 콘텐츠를 더 쉽게 찾는다 | Phase 2 완료 후 1차 테스트 | 테스트 과제 성공률, 첫 클릭까지 소요 시간 |
| H2 — 재노출 | 주기적으로 재노출된 콘텐츠는 그렇지 않은 콘텐츠보다 다시 확인되거나 활용될 가능성이 높다. 제품의 핵심 가설 | Phase 3 완료 후 2차 테스트 | 재노출 콘텐츠 vs 미노출 콘텐츠의 4주 내 원문 열람률 |
| H3 — AI 요약 | 짧은 요약으로 원문을 열지 않고도 내용을 판단할 수 있다 | Phase 2 완료 후 1차 테스트 | 요약만 보고 보관/삭제 결정한 비율 |
| H4 — 수집 경험 | 클라이언트 캡처를 포함한 원클릭·공유창 저장이 별도 앱 이동보다 간편하다 | Phase 3 | 저장 완료율, 본문 확보 비율 |
| H5 — 지속 사용 | 재노출과 검색을 함께 제공하면 일회성 저장 도구가 아닌 지속 사용 도구로 인식한다 | Phase 4 | 4주 유지율, 주 1회 이상 재노출 피드 확인 비율 |
| H6 — 북마크 구조조정 | 대량 가져오기 + 정리 화면을 거친 사용자는 그렇지 않은 사용자보다 유지율이 높다 | Phase 4 | 가져오기 사용자 vs 비사용자의 4주 유지율 |

## 14. 제품의 핵심 원칙

1. 저장은 빠르고 간편해야 하며, 저장하는 순간 본문까지 확보한다.
2. 저장한 자료를 다시 읽도록 강요하지 않는다. Inbox는 비우지 않아도 쌓이지 않는다.
3. 제목을 잊어버렸더라도 내용을 통해 찾을 수 있어야 한다.
4. 저장된 자료를 주기적으로 다시 발견할 기회를 제공한다. 이것이 제품의 존재 이유다.
5. AI는 자료를 이해하고 찾는 일을 돕되, 원본을 대체하지 않는다.
6. 사용자가 보관할 자료와 삭제할 자료를 쉽게 결정하도록 돕는다.
7. 사용자의 비용(시간, 돈, 개인정보)을 사용자가 통제할 수 있게 한다.
8. 장기적으로는 저장한 콘텐츠를 읽거나 듣는 등 원하는 방식으로 쉽게 소비할 수 있도록 발전한다.

**최종 목표: 저장한 콘텐츠를 잊어버리지 않고, 필요할 때 다시 찾고 실제로 활용할 수 있게 만드는 것.**
