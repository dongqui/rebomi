# 넷째 개발 묶음 — 웹 앱 뼈대 · 키워드 검색 · 보관 상태 · Issue 초안

**상태: 2026-11-18 사용자 승인 후 GitHub에 등록했다 — A=#32, B=#30, D=#31, E=#33. C는 승인 전에 뺐다. 이후의 기준은 GitHub Issue이며 이 문서는 갱신하지 않는다.**

## 묶음의 목표

**웹 앱을 디자인 파일의 모양으로 옮기고, 저장한 것을 단어로 찾고, 찾은 것을 보관하거나 지울 수 있게 한다.** 지금까지의 묶음은 저장(웹 URL, 확장)과 처리 파이프라인을 세웠다. 저장한 뒤에 할 수 있는 일은 아직 목록을 보는 것뿐이다.

## 이 묶음을 고른 이유

- 디자인 파일(`RebomiWeb`)이 지금 설계해 둔 화면은 **홈과 검색**이다. 보관함·Inbox·정리·휴지통·설정 화면은 디자인이 "다음 단계에서 설계한다"고 적어 두었다. 웹 화면은 디자인을 따르기로 했으므로(2026-11-17), 지금 만들 수 있는 화면은 홈과 검색이다.
- 홈과 검색에 필요한 것 가운데 **제품 결정을 기다리지 않는 것**을 모았다: 앱 뼈대, 최근 저장, 키워드 검색(SRCH-1), 결과에서의 보관·삭제.
- 보관 상태 변경(LIB-3~4)은 `product.md` §7 제안 단계의 Phase 1 "목록·상태 관리 기반"에서 남은 것이고, 검색 결과의 보관·삭제와 다음 묶음의 재노출 카드가 그대로 쓴다.
- Inbox 30일 자동 보관과 휴지통 30일 영구 삭제(LIB-2, LIB-4의 워커 잡)는 2026-11-18 사용자 의견으로 이 묶음에서 뺐다. Inbox·휴지통 화면이 생기는 보관함 화면 묶음으로 넘긴다. 요구사항 자체는 `library.md`에 P0로 그대로 있다.
- 다른 후보는 먼저 정해져야 할 것이 있다.
  - 요약(summary): LLM 제공자(architecture §9), D-13 요약 언어, D-12 캐시 공유 범위
  - 재노출(resurfacing): D-05 기본값, D-11 "나중에 다시 보기"
  - 의미·하이브리드 검색(SRCH-2~3): 임베딩 모델과 호스팅 방식(architecture §9)
  - 보관함·Inbox·휴지통·정리 **화면**: 디자인이 아직 없다
  - 북마크 가져오기(import): D-03, D-04

## 디자인과 문서가 다른 곳

구현 전에 어느 쪽을 따를지 정해야 한다. 이 묶음의 Issue에는 "설계에서 사용자에게 묻는 것"으로 넣었거나 범위에서 뺐다.

- **추출 수준의 표기.** 디자인은 "본문 확보 / 본문 일부 / 메타데이터만", 지금 웹과 확장은 "본문 / 일부 / 메타데이터만"이다 (A에서 묻는다).
- **재노출 카드의 "넘기기".** 디자인의 카드에는 "넘기기"가 있다. `resurfacing.md` RES-5의 액션(원문 열기, 나중에 다시 보기, 보관하기, 재노출 중단, 삭제하기)에는 없다. 이 묶음 밖이다 — 재노출 묶음을 나눌 때 정한다.
