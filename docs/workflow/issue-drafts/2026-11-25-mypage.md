라벨: `status:todo`

## 목표

로그인한 사용자가 자기 이름·이메일·요금제 이름을 조회하고 이름을 고칠 수 있는 API가 있다. 클라이언트는 `api-client`로 쓴다.

## PRD 참조

- `docs/features/mypage.md` §2 MY-2~5 / §5 이름, 요금제 / §6 완료 조건
- `docs/architecture.md` §3 인증 (`requireAuth`)

## 범위

**포함**

- 계정에 이름을 저장할 자리(DB)
- 내 계정 정보 조회(이름, 이메일, 요금제 이름)와 이름 수정의 계약(`packages/api-contract`), 서버 경로, `api-client` 함수
- 요금제 이름: 결제가 없으므로 모든 계정이 Free다
- `architecture.md` 갱신

**제외**

- 제공자에게서 이름을 받아 저장하는 것 — B
- 이름이 없을 때 이메일 앞부분을 보여주는 것 — 화면(D, E)
- 사용량, 결제 — billing

**설계에서 사용자에게 묻는 것**

- 경로와 응답의 모양, 컬럼 이름, 요금제 값의 이름과 저장 여부(지금 컬럼을 둘지, 응답에서만 고정값으로 줄지)

## 완료 조건

- [ ] 로그인한 사용자가 자기 이름(없으면 빈 값), 이메일, 요금제 이름을 조회한다
- [ ] 이름을 고치면 저장되고 다음 조회에 반영된다
- [ ] 이름은 앞뒤 공백을 떼고 1~50자다. 빈 이름과 50자를 넘는 이름은 거부되고 원인을 구분할 수 있는 에러를 받는다
- [ ] 로그인하지 않은 요청은 401 `UNAUTHORIZED`를 받는다
- [ ] 다른 사용자의 이름을 보거나 고칠 방법이 없다(대상은 늘 토큰의 사용자다)
- [ ] `api-client`에 조회·수정 함수가 있고 계약의 타입을 쓴다
- [ ] `pnpm lint && pnpm typecheck && pnpm test && pnpm build`가 통과한다

## B. [api] 가입할 때 제공자가 준 이름을 저장한다

라벨: `status:todo`

<!-- rebomi-issue | prd: docs/features/mypage.md | req: MY-2 -->

## 목표

Google 또는 Apple로 처음 가입하면 제공자가 준 이름이 계정의 이름이 된다.

## PRD 참조

- `docs/features/mypage.md` §2 MY-2 / §5 이름 / §7 의존
- `docs/features/account.md` §4, `docs/architecture.md` §3 (로그인, 모바일의 로그인 중계)

## 범위

**포함**

- 계정을 만들 때 제공자의 이름을 저장한다. 이미 있는 계정의 이름은 로그인으로 바뀌지 않는다
- Google: 이름을 받는 데 필요한 로그인 요청 변경(웹 로그인, 모바일 로그인 중계)
- Apple: 이름은 첫 로그인의 응답으로만 온다 — 그것을 서버까지 전달하는 변경(웹 로그인, 모바일 로그인 중계, 로그인 계약)
- `architecture.md` §3 갱신

**제외**

- 이미 가입한 계정에 이름을 채워 넣는 것 (비어 있는 채로 둔다 — 화면이 이메일 앞부분을 보여준다)

**설계에서 사용자에게 묻는 것**

- 로그인 계약의 변경 모양(Apple의 이름은 검증할 수 없는 값이다 — 클라이언트가 보낸 대로 받는지)
- Google에 이름 범위를 요청하면 동의 화면의 문구가 바뀐다

## 완료 조건

- [ ] Google로 처음 가입하면 Google 계정의 이름이 저장된다
- [ ] Apple로 처음 가입하고 Apple이 이름을 주면 그 이름이 저장된다. 주지 않으면 이름은 비어 있고 로그인은 된다
- [ ] 이름을 고친 뒤 다시 로그인해도 고친 이름이 그대로다
- [ ] 이 변경 전에 가입한 계정으로 로그인해도 실패하지 않고 이름은 비어 있다
- [ ] 저장되는 이름은 A의 길이 규칙을 따른다(넘으면 잘라 저장하거나 비운다 — 로그인을 막지 않는다)
- [ ] `pnpm lint && pnpm typecheck && pnpm test && pnpm build`가 통과한다

## 검증 방법

가짜 제공자 토큰을 쓰는 api 테스트, 웹·모바일 중계의 단위 테스트. 실제 계정 확인은 제공자 설정이 끝난 뒤

## 선행 Issue

- A (이름을 저장할 자리)
- #43 (모바일 로그인과 웹 중계 — PR #47, #48)
