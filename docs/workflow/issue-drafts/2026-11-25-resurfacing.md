# 재노출 (resurfacing) — Issue 초안

**상태: 승인됨 (2026-11-25). D-05를 추천안대로 정하고 8건을 등록하기로 했다. 문서 PR #51이 병합된 뒤 등록한다.**

## 범위

`docs/features/resurfacing.md`의 P0 전부(RES-1~8)를 나눈다. 제품의 차별점인데 코드에는 `contents.resurfacing_included` 컬럼 하나만 있다.

## 지금 있는 것

- `contents.resurfacing_included` (DB, 계약 `resurfacingIncluded`). 저장할 때 출처에 따라 값을 넣는다.
- `contents.source` (`extension` / `mobile` / `web` / `import`), `saved_at`, 보관 상태, 링크 상태.
- 보관·삭제·복구 API(#30)와 웹의 토스트·확인 대화상자(#33).
- 워커에는 주기적으로 도는 잡이 없다. 재노출 회차, 노출 기록, 사용자별 설정을 담을 곳도 없다.

## 정한 것 (2026-11-25)

D-05의 아래 항목을 추천안대로 정해 `docs/features/resurfacing.md` §5에 옮겼다. 1~3이 `status:todo`가 됐다.

| 정한 것 | 결정 |
| --- | --- |
| 회차를 만드는 주기의 기본값과 회당 개수 | 주 3회(월·수·금), 회당 최대 5개 |
| 홈의 "오늘의 재발견"과 주기의 관계 | 홈은 가장 최근 회차에서 아직 처리하지 않은 카드를 보여준다. 다 처리하면 마쳤다는 화면이고 다음 회차까지 새 카드가 없다 |
| 후보가 모자랄 때 | 있는 만큼만 고른다. 하나도 없으면 회차를 만들지 않고 홈은 안내를 보인다 |
| "최근 7일 내 확인"의 뜻 | 카드에서 원문을 열었거나, 자세히 보기를 열었거나, 액션(나중에·보관·중단·삭제)을 한 것 |
| "나중에 다시 보기"의 기간 | 7일 뒤부터 다시 후보가 된다 ("이전 재노출 이후 14일" 대신) |

**D-05의 남은 부분**(사용자가 고르는 빈도의 선택지)은 정하지 않았다. 5(설정)가 이것을 기다린다.

**D-11** (Inbox의 "나중에 보기"와 같은 동작인가)은 Inbox 화면이 생길 때 정해도 된다. 이 묶음은 재노출 카드의 "나중에 다시 보기"만 만든다.

**D-24** (재노출 이메일의 세부)에 8이 걸려 있다.
