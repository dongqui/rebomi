# 둘째 개발 묶음 — Chrome 확장 저장 · Issue 초안

**상태: 2026-11-16 사용자 승인 후 GitHub에 등록했다 — A=#17, B=#19, C=#18, D=#20. 이후의 기준은 GitHub Issue이며 이 문서는 갱신하지 않는다.**

## 묶음의 목표

**Chrome 확장에서 현재 페이지를 한 번의 클릭으로 저장하고, 그 순간 브라우저에 보이는 본문까지 함께 보낸다.** 첫 묶음(#1~#7)이 웹 URL 저장과 비동기 처리 파이프라인을 세웠고, 이 묶음은 그 위에 "저장하는 쪽이 본문도 함께 보낸다"는 공통 원칙을 처음 구현한다.

## 이 묶음을 고른 이유

- `product.md` §7 제안 단계의 Phase 1(계정, 웹 URL 저장, Chrome 확장 저장, 목록·상태 관리 기반, 비동기 처리 파이프라인)에서 남은 것 가운데 **결정 대기 없이 바로 실행할 수 있는 것**이다.
- 본문을 함께 받는 저장 계약은 iOS·Android 공유 저장(CAP-3, CAP-4)도 그대로 쓴다. 요약(summary)의 품질도 여기서 확보한 본문에 달려 있다.
- 다른 후보는 먼저 결정이 필요하다.
  - 요약(summary): LLM 제공자(architecture §9), D-13 요약 언어, D-12 캐시 공유 범위
  - 재노출(resurfacing): D-05 기본값
  - 관리(library LIB-1~4): D-14, D-15가 보관 상태 전이와 맞물린다
