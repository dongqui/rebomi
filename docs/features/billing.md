# 요금제와 한도 (billing)

원본: PRD v0.5 §9, §5.6(요금제), §8(결제), §11.5 · 집행 위치: [architecture §7](../architecture.md#7-비용-통제와-사용량-집행)

## 1. 목적

사용자 한 명이 1,300개를 가져오면 요약·임베딩 비용이 즉시 발생한다. 무료 한도로 비용을 통제하고 Pro 구독으로 수익을 만든다. 사용자가 자신의 비용을 통제할 수 있어야 한다(원칙 7).

## 2. 범위

**P0 포함**

| ID | 요구사항 |
| --- | --- |
| BILL-1 | Free와 Pro 두 요금제가 있고 아래 표의 한도가 적용된다 |
| BILL-2 | 저장 콘텐츠 수와 가져오기 한도를 서버에서 집행한다 |
| BILL-3 | AI 요약·임베딩 월 한도를 서버에서 집행한다 |
| BILL-4 | Pro 구독을 결제하고, 설정에서 요금제를 확인한다 |

| 항목 | Free | Pro (월 구독) |
| --- | --- | --- |
| 저장 콘텐츠 수 | 500개 | 무제한 |
| 북마크 가져오기 | 최초 1회, 500개까지 | 무제한 |
| AI 요약·임베딩 | 월 300개 | 월 3,000개 |
| 재노출 | 홈 피드 | 홈 피드 + 푸시 + 이메일 다이제스트(P1) |
| 검색 | 전체 기능 | 전체 기능 |

**수치는 잠정이다.** 출시 전 실제 비용을 측정해 조정하고, Phase 4의 비용 측정 결과로 확정한다.

**제외**

- 이메일 다이제스트 (P1)
- 연간 구독, 팀 요금제 등 (원문에 없음)

## 3. 플랫폼별 역할

| 플랫폼 | 역할 |
| --- | --- |
| 서버 | 요금제 상태, 사용량 집계, 한도 집행, 결제 웹훅 |
| 워커 | AI 한도 집행(잡 실행 직전), 월 사용량 초기화 |
| 웹 | 요금제 화면, 결제, 남은 한도 표시 |
| 모바일 | 요금제·남은 한도 표시. 앱 내 결제 여부는 D-10 |
| 확장 | 한도 초과로 저장이 실패하면 이유 표시 |

## 4. 사용자 흐름

1. Free로 시작한다. 설정에서 요금제와 사용량을 본다.
2. 한도에 가까워지거나 넘으면 안내를 받는다.
3. Pro를 결제하면 한도가 바뀐다.

## 5. 동작 규칙과 예외

- 한도는 서버에서만 집행한다. 클라이언트는 표시만 한다.
- 대량 가져오기에서 AI 한도를 넘는 분량은 메타데이터만 등록한다(최근 북마크부터 처리). **[원문]**
- 그 밖의 초과 동작은 원문에 없다(D-03): 직접 저장이 500개를 넘을 때, 직접 저장이 월 AI 한도를 넘을 때, Free 가져오기 파일이 500개를 넘을 때.
- 저장 개수 한도와 AI 처리 한도는 **서로 다른 한도이고 초과 동작도 다를 수 있다.** 하나로 합쳐 구현하지 않는다.
- 비용 통제 장치(토큰 상한, 캐시, 링크 소멸 생략)는 요금제와 무관하게 항상 적용된다. → [summary SUM-6](summary.md)
- 목표 단위 경제: Pro 사용자 1인당 월 AI 비용 ≤ 구독료의 15%.

## 6. 완료 조건

- [ ] 사용자의 요금제와 이번 달 사용량(저장 수, AI 처리 수)이 설정에 표시된다.
- [ ] Free 사용자의 저장·가져오기·AI 처리가 각 한도에서 D-03에 정한 대로 동작한다.
- [ ] AI 월 한도는 달이 바뀌면 초기화된다.
- [ ] 한도 판정이 서버에서 이뤄져, 클라이언트를 우회한 요청도 한도를 넘지 못한다.
- [ ] Pro 결제가 성공하면 한도가 즉시 바뀌고, 실패하면 Free로 남는다.
- [ ] 구독이 끝나면 Free 한도로 돌아가고, 이미 저장된 데이터는 D-10에 정한 대로 처리된다.
- [ ] 푸시 제공 대상이 D-02에 정한 대로 적용된다.
- [ ] 계측: Free→Pro 전환, 한도 도달이 기록된다.
