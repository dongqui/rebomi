# 북마크 가져오기 (import)

원본: PRD v0.5 §2.2 시나리오 C, §4.1 "기존 북마크 가져오기", §9, §11.2, §11.7 · 공통 규칙: [architecture §4 상태](../architecture.md#4-콘텐츠의-공통-상태), [§7 비용 통제](../architecture.md#7-비용-통제와-사용량-집행)

## 1. 목적

쌓아둔 브라우저 북마크를 한 번에 옮겨, 검색하고 정리하고 골라서 재노출로 이어지게 한다. 대량 가져오기 + 정리 + 재노출을 묶은 "북마크 구조조정" 경험은 경쟁 제품과의 차별점이다(H6).

## 2. 범위

**P0 포함**

| ID | 요구사항 |
| --- | --- |
| IMP-1 | Chrome 북마크 HTML 파일을 가져와 다수 URL을 일괄 등록한다 |
| IMP-2 | 폴더명을 "가져온 폴더" 속성으로 보존한다. 보관함 필터와 재노출 포함 여부에 쓴다 |
| IMP-3 | 중복을 제거한다 (정규화된 URL 기준 — [capture CAP-6](capture.md)과 같은 규칙) |
| IMP-4 | 진행 상태를 표시한다 |
| IMP-5 | 응답 없음·404·도메인 소멸 링크를 **링크 소멸**로 분류한다. 요약·임베딩을 생략하고 정리 화면에서 일괄 삭제를 제안한다 |
| IMP-6 | 메타데이터 수집과 요약은 순차로 진행한다(최근 북마크부터). 본문·요약이 준비되지 않아도 가져온 북마크는 **즉시** 목록과 키워드 검색에 나타난다 |
| IMP-7 | 가져온 콘텐츠는 재노출 대상에서 기본 제외한다 |

**제외**

- Chrome 외 브라우저·다른 서비스의 내보내기 형식 (원문에 없음)
- 중복·유사 콘텐츠 정리, 오래된 콘텐츠 정리 추천 (P1, 단 D-01)

## 3. 플랫폼별 역할

| 플랫폼 | 역할 |
| --- | --- |
| 웹 | 파일 업로드, 진행 상태 표시, 완료 후 정리 화면 진입 유도 |
| 서버 | 파일 파싱, 중복 제거, 일괄 등록, 한도 집행 |
| 워커 | 순차 메타데이터 수집, 링크 생존 확인, 본문 서버 fetch, 요약·임베딩 |
| 확장·모바일 | 없음. 설정에 "북마크 가져오기" 진입점이 있으나(원문 §5.6) 가져오기 자체는 웹 기능이다 |

## 4. 사용자 흐름

1. 설정 또는 가져오기 화면에서 Chrome 북마크 HTML 파일을 올린다.
2. 서버가 파싱·중복 제거 후 콘텐츠를 등록한다. 등록된 북마크는 곧바로 목록과 키워드 검색에 나타난다.
3. 진행 상태가 표시되는 동안 워커가 최근 북마크부터 메타데이터 수집 → 링크 생존 확인 → 본문 추출 → 요약을 진행한다.
4. 완료 후 정리 화면으로 진입을 유도한다. 링크 소멸 콘텐츠의 일괄 삭제를 제안한다. → [library LIB-7](library.md)
5. 사용자가 가져온 폴더 단위로 재노출에 포함할 것을 고른다. → [resurfacing RES-3](resurfacing.md)

## 5. 동작 규칙과 예외

- 가져온 콘텐츠의 본문은 서버 fetch(3순위)로 확보한다. 실패하면 메타데이터만 남는다.
- 링크 소멸 판정이 요약보다 앞선다. 링크 소멸 콘텐츠에는 AI 비용을 쓰지 않는다.
- 가져온 콘텐츠를 재노출에서 기본 제외하는 이유: 1,300개를 가져온 직후 "오래된 자료 우선"을 그대로 적용하면 피드가 몇 달간 저품질 북마크로 채워져 재노출 피로도의 가장 큰 원인이 된다.
- AI 처리 한도를 넘는 분량은 메타데이터만 등록한다(최근 북마크부터 처리하므로 오래된 것이 남는다). **[원문 §9]**
- Free는 가져오기 최초 1회, 500개까지다. 초과분의 처리와 "1회"의 판정은 D-03.
- 일시적 접근 실패와 링크 소멸의 구분은 D-04.

## 6. 완료 조건

- [ ] 폴더가 있는 Chrome 북마크 HTML을 올리면 모든 유효 URL이 등록되고 각 콘텐츠에 가져온 폴더명이 남는다.
- [ ] 파일 안의 중복 URL, 이미 저장된 URL은 다시 등록되지 않는다.
- [ ] 등록 직후(요약 전) 가져온 북마크가 목록에 보이고 제목·URL 키워드 검색에 잡힌다.
- [ ] 처리 중 진행 상태(전체 대비 완료 수)가 갱신된다.
- [ ] 404를 돌려주는 URL은 링크 소멸로 표시되고, 요약·임베딩 잡이 실행되지 않는다.
- [ ] 처리 순서가 최근 북마크부터다.
- [ ] 가져온 콘텐츠는 사용자가 포함시키기 전까지 재노출 피드에 나오지 않는다.
- [ ] 북마크 형식이 아닌 파일은 거부되고 이유가 표시된다.
- [ ] 1,000개 이상의 파일도 등록 단계가 사용자를 기다리게 하지 않는다(등록은 즉시, 처리는 비동기).
- [ ] 계측: 가져오기 실행, 가져온 수, 링크 소멸 수가 기록된다 (대량 가져오기 이용률, H6).
