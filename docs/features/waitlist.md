# 대기 명단 랜딩 (waitlist)

원본: PRD v0.5에는 없다. 2026-11-17에 추가했다. 화면과 문구의 기준은 디자인 프로젝트의 `RebomiLanding`이다 · 공통 규칙: [architecture §8 개인정보](../architecture.md#8-개인정보)

> 기본 문서 구조에 없던 문서다. 제품 기능(P0)이 아니라 출시 전에 수요를 확인하는 광고 랜딩이고, 들어갈 자리가 없어 만들었다.

## 1. 목적

Rebomi가 열리기 전에 광고로 들어온 방문자에게 무엇을 만드는지 보여 주고, 관심 있는 사람의 이메일과 저장 습관에 대한 짧은 답을 받는다. 답은 수요를 판단하는 데 쓴다. 의견을 최대한 모으는 것이 목적이므로, 끝까지 가지 않은 방문자의 답도 남긴다.

## 2. 범위

**포함**

| ID | 요구사항 |
| --- | --- |
| WAIT-1 | 웹의 첫 주소(`/`)는 로그인 여부와 무관하게 랜딩 페이지다. 로그인한 사용자의 화면(지금의 저장·목록)은 `/app`에 있다 |
| WAIT-2 | 랜딩은 디자인의 구성을 따른다: 히어로(헤드라인, 설명, 등록 버튼, 고른 경우 그림), 문제 제기(앱마다 쌓인 저장함 더미), 하는 일 네 가지(다시 만나기 / 요약 / 기억으로 찾기 / 쓰던 앱에서 저장), 마지막 등록 버튼, 푸터 (2026-11-19 디자인 변경 반영) |
| WAIT-3 | 등록 버튼을 누르면 대화상자가 열려 질문 네 개 → 이메일 → 완료 순으로 진행한다. 이전 단계로 돌아갈 수 있고, 닫았다 다시 열면 하던 단계에서 이어진다 |
| WAIT-4 | 이메일을 내면 그 응답에 이메일이 저장된다. 저장에 성공한 뒤에만 완료 화면을 보여 준다 |
| WAIT-5 | 지금은 방문자의 브라우저 언어와 무관하게 영어로 보여 준다. 한국어 문구는 갖고 있되 보여 주지 않는다 (2026-11-20: 브라우저 언어로 고르던 것을 바꿈) |
| WAIT-6 | 헤드라인은 네 가지(진전 같지만 다시 안 봄 / 저장하고 잊음 / 여기저기 흩어짐 / 찾을 수 없음)이고 광고 소재에 맞춰 주소로 고른다. 지정이 없으면 "진전 같지만 다시 안 봄"이다 (2026-11-19: 세 가지에서 네 가지로, 기본값 변경) |
| WAIT-7 | 라이트·다크는 기기 설정을 따른다 |
| WAIT-8 | 설문의 답은 고를 때마다 서버에 저장된다. 이메일까지 가지 않고 그만둔 방문자의 답도 남는다 |
| WAIT-9 | 질문은 모두 하나만 고른다. 질문마다 마지막 선택지가 "기타"이고, 고르면 직접 적는 칸이 열린다. 적은 글도 응답에 저장된다 (2026-11-19) |
| WAIT-10 | 히어로의 그림은 네 가지(글만 / 카드 / 알림 / 휴대폰)이고 광고 소재에 맞춰 주소로 고른다. 지정이 없으면 글만이다 (2026-11-19) |
| WAIT-11 | 배포된 랜딩은 API 서버 없이 동작한다. 설문 응답은 웹이 함께 가진 서버 경로(`/api`)로 저장한다 (2026-11-19) |
| WAIT-12 | 이메일을 받는 단계에서 무엇을 왜 받는지, 얼마나 보관하는지, 삭제를 어디로 요청하는지 알린다 (2026-11-19, D-16 결정) |

**제외**

- 대화상자를 열기만 하고 아무것도 고르지 않은 방문의 기록, 광고 유입 파라미터의 기록 (D-17)
- 등록 확인 메일, 초대 메일 발송
- 휴대폰 그림 안 화면의 조작 — 디자인은 조작 가능한 모바일 목업을 넣었으나, 랜딩에는 첫 화면(재노출 카드)을 정적으로 그린다 (2026-11-17). 카드와 알림 그림도 누를 수 없는 그림이다
- 랜딩에서의 로그인·가입 진입점 — 디자인에 없다
- "차분하게" 섹션 — 디자인에서 기본으로 숨겨졌다. 랜딩에 두지 않는다 (2026-11-19)
- 사용 방법 섹션, 등록 버튼 아래의 안내 문구("질문 네 개와 이메일, 1분쯤") — 디자인에서 빠졌다 (2026-11-19)
- 지불 의향 질문 — 디자인의 새 설문에 없다 (2026-11-19)

## 3. 플랫폼별 역할

| 플랫폼 | 역할 |
| --- | --- |
| 서버 | 설문 응답 저장 API(인증 없음): 응답 생성·갱신, 이메일 저장. 같은 계약이 두 곳에 있다 — API 서버(`apps/api`)와 웹의 `/api`(WAIT-11) |
| 웹 | 랜딩 페이지, 등록 대화상자, 배포된 랜딩의 응답 저장 경로, 로그인한 화면의 `/app` 이전 |
| 확장·모바일 | 없음 |

## 4. 사용자 흐름

1. 방문자가 광고를 눌러 `/`에 온다. 주소에 헤드라인·그림 지정이 있으면 그것을 본다.
2. 등록 버튼을 누른다. 대화상자가 첫 질문으로 열리고, 이 응답의 ID가 브라우저에서 만들어진다. 이때는 아직 서버에 아무것도 없다.
3. 첫 질문에서 선택지를 고른다. 그 ID로 서버에 응답이 만들어지고, 다음 질문으로 넘어간다.
4. 나머지 질문에 답한다. 고를 때마다 같은 응답이 갱신되고 다음으로 넘어간다. "기타"를 고르면 넘어가지 않고 직접 적는 칸과 "다음"이 나온다. 적고(적지 않아도 된다) "다음"이나 Enter로 넘어가면 적은 글이 함께 저장된다.
5. 이메일을 적고 등록한다. 형식이 틀리면 그 자리에서 알린다. 이 단계에 수집 고지가 있다.
6. 서버가 같은 응답에 이메일을 저장하면 완료 화면을 본다. 저장에 실패하면 이메일 단계에 머물고 다시 시도할 수 있다.

## 5. 동작 규칙

**결정된 것 (2026-11-17)**

- `/`는 항상 랜딩이다. 로그인 확인을 기다리지 않고 바로 뜬다. 로그인한 화면은 `/app`으로 옮기고, 로그인 뒤의 이동과 로그인이 필요한 화면의 보호도 `/app` 기준으로 바꾼다.
- 이메일과 설문 답을 서버에 저장한다.
- 언어는 브라우저 언어로 고른다. → 2026-11-20에 바뀌었다. 아래 참고.
- 휴대폰 화면은 정적이다.
- 톤은 디자인 기본값인 "웜 페이퍼"다.

**결정된 것 (2026-11-17, 같은 날 뒤에 바꿈)**

- 설문의 답은 고를 때마다 저장한다(WAIT-8). 대화상자가 열릴 때 브라우저가 응답 ID를 만들고, 첫 답을 고르는 순간 그 ID로 서버에 응답이 생기며, 이후의 답과 이메일은 같은 응답을 갱신한다. 어디까지 답했는지는 응답에 남은 답으로 알 수 있다.
- 답을 저장하는 요청이 실패해도 설문 진행을 막지 않는다. 방문자에게 오류를 보이지 않고 다음 답을 저장할 때 지금까지의 답을 함께 보낸다. 이메일 저장의 실패만 방문자에게 알린다(WAIT-4).
- 같은 이메일로 여러 번 등록할 수 있다. 응답마다 따로 남고, 이메일로 묶거나 막지 않는다.

**결정된 것 (2026-11-19)**

- 화면은 바뀐 디자인을 따른다: 새 설문 네 질문, 헤드라인 네 가지, 히어로 그림 네 가지, 본문 구성(WAIT-2, 6, 9, 10).
- 설문 응답은 웹의 `/api`로 저장하고, DB는 Supabase(Postgres)에 둔다. 지금 배포하는 것은 랜딩과 설문뿐이다 — 로그인한 화면(`/app`)과 API 서버·워커는 배포하지 않는다(WAIT-11).
- 수집 고지(WAIT-12, D-16): 받는 것은 이메일과 설문 답, 쓰는 곳은 출시 안내와 수요 파악이다. **받은 날부터 1년 동안 보관한 뒤 지운다.** 그 전의 삭제 요청은 `projectn.contact@gmail.com`으로 받는다. 이 내용을 이메일 단계에 적는다. 디자인에 없는 문구다.
- 이전 설문(쌓이는 곳·다시 보는 빈도·가장 도움이 될 것·지불 의향)의 답은 버린다. 공개 배포 전이라 실제 방문자의 응답이 없다.

**결정된 것 (2026-11-20)**

- 랜딩은 일단 영어로만 보여 준다(WAIT-5). 브라우저 언어가 한국어여도 영어다. 한국어 문구와 응답의 `locale` 값 `ko`는 지우지 않는다 — 다시 언어를 고르게 할 때 쓴다. 그때 무엇으로 고를지(브라우저 언어 / 주소)는 정하지 않았다.

**그 밖의 규칙**

- 질문과 선택지의 문구·순서는 디자인을 따른다. 질문은 넷이다: 지금 주로 하는 일, 저장할 때 그걸로 하고 싶은 것, 가장 답답한 점, Rebomi가 한 가지를 도와준다면.
- 답은 문구가 아니라 언어와 무관한 고정 키로 저장한다 — 한국어와 영어 응답을 함께 집계할 수 있어야 한다. "기타"에 적은 글만 방문자가 쓴 그대로다.
- "기타"에 적은 글은 500자까지이고 앞뒤 공백을 뗀다. 그 질문의 답이 "기타"일 때만 저장한다 — 다른 답으로 바꾸면 저장된 글을 지운다. 화면에서는 돌아와 다시 "기타"를 고르면 적어 둔 글이 남아 있다.
- "기타"에 적는 글은 글자마다 저장하지 않는다. 다음 단계로 넘어갈 때 저장한다. "기타"를 고른 것 자체는 고르는 순간 저장한다(WAIT-8).
- 어느 언어, 어느 헤드라인, 어느 히어로 그림으로 등록했는지 함께 저장한다 (광고 소재별 비교).
- 이메일은 앞뒤 공백을 떼고 대소문자를 구분하지 않는다 ([account](account.md) §4와 같다).
- 응답 저장 API는 인증이 없고 이메일 없이도 응답을 만들 수 있으므로 같은 출처의 과도한 요청을 제한한다. API 서버는 IP당 1분 60회로 제한한다. 웹의 `/api`는 배포 쪽 방화벽에서 제한한다 ([architecture §8](../architecture.md#8-개인정보)).
- 응답 ID를 아는 쪽만 그 응답을 갱신할 수 있고, API는 저장된 응답을 돌려주지 않는다(남의 이메일과 답을 읽을 길이 없다). Supabase에서도 이 테이블은 바깥(Data API)에서 읽거나 쓸 수 없게 막는다.
- 완료 화면을 본 뒤 같은 페이지에서 등록 버튼을 다시 누르면 완료 화면을 다시 보여 준다. 새 응답을 만들지 않는다 — 한 방문자가 응답을 여러 개 남기는 것을 줄인다. 페이지를 새로 열면 새 응답으로 시작한다. (2026-11-17 결정)
- 헤드라인은 주소의 `?h=`로 고른다: `forgot`(저장하고 잊음), `scattered`(여기저기 흩어짐), `find`(찾을 수 없음), `progress`(진전 같지만 다시 안 봄). 없거나 모르는 값이면 `progress`다. `progress`일 때만 설명 문구가 다르다(디자인).
- **[제안]** 히어로 그림은 주소의 `?hero=`로 고른다: `card`(카드), `notice`(알림), `phone`(휴대폰). 없거나 모르는 값이면 글만이다. 디자인은 네 가지를 시안의 선택지로만 두었고, 주소로 고르는 방식은 헤드라인을 따라 정했다.
- ~~언어는 요청의 `Accept-Language`에서 가장 선호하는 언어 하나로 정한다.~~ 2026-11-20부터 랜딩에는 적용하지 않는다(영어 고정). 로그인한 화면(`/app`)은 여전히 이 규칙으로 언어를 정한다.
- 고르면 저장을 기다리지 않고 0.2초 뒤 다음 질문으로 넘어간다. "기타"는 넘어가지 않는다.
- 검색 엔진의 색인을 막지 않는다. 언어별 제목·설명 메타를 두고 공유 이미지는 두지 않는다. (2026-11-17 결정)
- 대기 명단 이메일은 계정이 아니다. 이 이메일로 `users` 행을 만들지 않고, 나중에 그 이메일로 가입해도 자동으로 연결하지 않는다.

## 6. 완료 조건

- [ ] 로그인하지 않은 브라우저로 `/`를 열면 로그인 화면으로 넘어가지 않고 랜딩이 보인다.
- [ ] 로그인한 사용자는 `/app`에서 저장과 목록을 지금과 똑같이 쓴다. 로그인하지 않고 `/app`을 열면 로그인 화면으로 간다. 로그인에 성공하면 `/app`으로 간다.
- [ ] 브라우저 언어가 한국어여도 랜딩과 등록 대화상자가 영어로 보인다.
- [ ] 주소로 헤드라인을 지정하면 그 헤드라인이, 지정이 없거나 모르는 값이면 기본 헤드라인(`progress`)이 보인다.
- [ ] 주소로 히어로 그림을 지정하면 그 그림이, 지정이 없거나 모르는 값이면 글만 보인다.
- [ ] 등록 버튼 → 질문 네 개 → 이메일 → 완료까지 키보드만으로 진행할 수 있다.
- [ ] "기타"를 고르면 다음 질문으로 넘어가지 않고 적는 칸이 열린다. 적고 넘어가면 그 글이 DB에 남는다. 적지 않고도 넘어갈 수 있다.
- [ ] "기타"에서 다른 답으로 바꾸면 DB에 남아 있던 글이 지워진다.
- [ ] 이메일 형식이 틀리면 서버로 보내지 않고 그 자리에서 알린다.
- [ ] 이메일 단계에 수집 항목, 목적, 보관 기간(1년), 삭제 요청 주소가 보인다.
- [ ] 대화상자를 열기만 하고 닫으면 DB에 아무것도 남지 않는다.
- [ ] 첫 질문에 답하면 응답이 DB에 생기고, 답을 고르거나 바꿀 때마다 같은 응답이 갱신된다. 언어, 헤드라인, 히어로 그림도 함께 남는다.
- [ ] 두 번째 질문까지 답하고 닫으면 그 두 답이 이메일 없이 DB에 남는다.
- [ ] 이메일을 내면 같은 응답에 이메일이 남는다. 응답이 하나 더 생기지 않는다.
- [ ] 이메일 저장이 실패하면 완료 화면이 나오지 않고, 다시 시도할 수 있다.
- [ ] 답 저장이 실패해도 설문은 계속 진행되고, 다음 저장이 성공하면 그때까지의 답이 모두 남는다.
- [ ] 같은 이메일로 두 번 등록하면 응답이 두 개 남는다.
- [ ] 화면 폭 860px 이하에서 한 단으로 바뀌고, 560px 이하에서 대화상자가 화면을 채운다 (디자인 기준).
