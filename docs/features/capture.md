# 콘텐츠 수집 (capture)

원본: PRD v0.5 §3, §4.1, §8(클라이언트), §11.1, §11.6, §11.8 · 공통 규칙: [architecture §4 상태](../architecture.md#4-콘텐츠의-공통-상태), [§5 흐름](../architecture.md#5-수집--처리--검색-흐름)

## 1. 목적

어디서든 몇 번의 클릭으로 저장하고, **저장하는 순간 본문까지 확보한다.** 타깃 사용자의 주요 출처(Reddit, YouTube, X, Instagram)는 서버 추출이 가장 어려우므로 추출의 1순위는 클라이언트다.

## 2. 범위

**P0 포함**

| ID | 요구사항 |
| --- | --- |
| CAP-1 | 웹에서 URL을 입력해 저장한다 |
| CAP-2 | Chrome 확장에서 현재 페이지를 원클릭 저장한다. 저장 시점에 렌더링된 DOM에서 본문·제목·대표 이미지를 추출해 전송한다. 로그인·페이월 뒤 페이지, SNS 게시물도 사용자가 보는 그대로 캡처한다 |
| CAP-3 | iOS에서 공유 메뉴로 저장한다. 메인 앱으로 전환하지 않고 공유창(Share Extension) 안에서 끝난다. Safari에서 공유하면 페이지 본문(JavaScript preprocessing)도 함께 받는다 |
| CAP-4 | Android에서 공유 메뉴로 저장한다. Share Intent 기반 저장 전용 UI가 공유된 텍스트·URL을 받는다 |
| CAP-5 | 제목, URL, 도메인, 대표 이미지, 저장일을 수집한다 |
| CAP-6 | 정규화된 URL(트래킹 파라미터 제거) 기준으로 중복을 감지하고, 저장 성공·중복 여부를 즉시 표시한다 |
| CAP-7 | 콘텐츠마다 추출 수준(본문 / 일부 / 메타데이터만)을 저장하고 화면에 표시한다 |
| CAP-8 | 저장 후 AI 처리는 서버에서 비동기로 하고, 실패하면 재시도한다 |
| CAP-9 | YouTube는 자막 API에 접근할 수 있으면 자막을 본문으로 쓰고, 아니면 제목·설명으로 처리한다 |
| CAP-10 | 클라이언트 캡처 전에 "이 페이지 본문도 저장됩니다"를 안내한다 |
| CAP-11 | 확장과 공유 확장은 사용자 계정으로 저장한다. 모바일 공유 확장은 메인 앱과 로그인 세션을 공유한다(iOS App Group, Android 공유 저장소) |

지원 콘텐츠: 일반 웹페이지, 블로그·뉴스, Reddit 게시물, YouTube 동영상, X·Instagram 등 SNS 링크.

**제외**

- 다른 Chromium 브라우저, Firefox (P1 검토)
- PWA
- 북마크 대량 가져오기 → [import](import.md)

## 3. 플랫폼별 역할

| 플랫폼 | 역할 | 본문 확보 방식 |
| --- | --- | --- |
| 확장 | 원클릭 저장 UI, DOM 본문 추출 | 클라이언트 캡처 (1순위) |
| iOS | Share Extension 저장 UI | Safari는 클라이언트 캡처(1순위), 다른 앱은 공유 텍스트(2순위) |
| Android | Share Intent 저장 UI | 공유 텍스트(2순위), 본문은 서버 보조 추출 |
| 웹 | URL 입력 저장 | 없음 — 서버 fetch(3순위) |
| 서버 | 저장 API, 중복 감지, 메타데이터 수집·보조 추출 잡 | 1·2순위가 없거나 실패했을 때 서버 fetch |

## 4. 사용자 흐름

1. 사용자가 확장 버튼·공유 메뉴·URL 입력 중 하나로 저장을 요청한다.
2. 클라이언트가 확보한 것(URL, 그리고 가능하면 제목·본문·이미지)을 서버로 보낸다.
3. 서버가 URL을 정규화하고, 이미 있으면 **중복**으로, 없으면 **저장 성공**으로 즉시 응답한다.
4. 모바일 공유창은 결과를 보여준 뒤 원래 앱으로 돌아간다.
5. 서버가 비동기로 메타데이터 수집 → (필요하면) 보조 추출 → 요약·임베딩을 진행한다. → [summary](summary.md)

## 5. 동작 규칙과 예외

**본문 추출 우선순위**

| 순위 | 방식 | 적용 | 결과 추출 수준 |
| --- | --- | --- | --- |
| 1 | 클라이언트 캡처 | Chrome 확장, iOS Safari 공유 | 본문 |
| 2 | 공유 텍스트 | 모바일 앱 공유 (Reddit, X 앱 등) | 일부 |
| 3 | 서버 fetch | 웹 URL 입력, 북마크 가져오기, 1·2 실패 시 | 본문 (공개 페이지) |
| 4 | 메타데이터만 | 1~3 모두 실패 | 메타데이터만 (제목·OG 설명·도메인으로 검색 가능) |

- 추출이 실패해도 저장은 성공한다. 추출 수준이 낮아질 뿐이다.
- 중복이면 새 콘텐츠를 만들지 않는다. **[제안]** 중복 저장 시 기존 콘텐츠에 더 높은 수준의 본문이 들어오면 갱신할지는 원문에 없다 — 구현 Issue의 설계에서 정한다.
- UI 형태는 운영체제 제약에 따라 달라도 저장 경험은 최대한 일치시킨다.
- 모바일 공유 확장은 메인 앱과 다른 실행 환경이다. 다음을 별도로 검증한다: 로그인 세션 공유, 네트워크 오류, 저장 완료 확인, 공유창 종료 동작. iOS 확장은 메모리 120MB 제한을 설계 전제로 둔다.
- 저장 개수 한도를 넘었을 때의 동작은 D-03.

## 6. 완료 조건

- [ ] 웹에서 유효한 http(s) URL을 저장하면 목록에 즉시 나타난다. 유효하지 않은 입력은 저장되지 않고 이유가 표시된다.
- [ ] 같은 페이지를 트래킹 파라미터만 다르게 두 번 저장하면 두 번째는 중복으로 표시되고 콘텐츠가 늘지 않는다.
- [ ] 확장으로 로그인이 필요한 페이지를 저장하면 추출 수준이 "본문"이고, 서버가 그 URL을 다시 fetch하지 않는다.
- [ ] iOS Safari에서 공유하면 메인 앱이 열리지 않고 저장이 끝나며 추출 수준이 "본문"이다.
- [ ] iOS·Android에서 다른 앱(예: Reddit)의 공유로 저장하면 공유창에서 성공이 표시되고 원래 앱으로 돌아간다.
- [ ] 메인 앱에 로그인한 상태면 공유 확장에서 다시 로그인하지 않는다. 로그아웃 상태면 저장되지 않고 로그인이 필요함을 알린다.
- [ ] 공유 확장에서 네트워크가 끊기면 실패가 표시되고, 성공으로 보이지 않는다.
- [ ] 서버가 본문을 가져오지 못한 콘텐츠는 "메타데이터만"으로 표시되고 제목·도메인으로 검색된다.
- [ ] 모든 콘텐츠의 추출 수준이 목록·상세에 표시된다.
- [ ] 확장의 첫 캡처 전에 본문 저장 안내가 표시된다.
- [ ] 계측: 저장 시도·완료, 추출 수준이 기록된다 (H4: 저장 완료율, 본문 확보 비율).
