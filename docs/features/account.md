# 계정과 동기화 (account)

원본: PRD v0.5 §3.2~3.3(계정 동기화, 세션 공유), §4.1(기기 간 동기화), §5.6(설정), §6(계정 P0), §11.8 · 공통 규칙: [architecture §3 인증](../architecture.md#3-인증과-기기-동기화)

> **[제안으로 추가한 문서]** 기본 문서 구조에는 없었다. 6장 P0의 "회원가입, 로그인, 기기 간 동기화"와 5.6의 내보내기·삭제가 들어갈 기능 문서가 없어 만들었다. 원문에 근거가 적어 대부분이 미결정이다.

## 1. 목적

어느 기기에서 저장하든 같은 계정의 콘텐츠로 모이게 한다. 사용자의 데이터는 본인만 본다.

## 2. 범위

**P0 포함 [원문 §6]**

| ID | 요구사항 |
| --- | --- |
| ACC-1 | 회원가입한다 |
| ACC-2 | 로그인한다. 웹, Chrome 확장, iOS, Android 모두에서 같은 계정을 쓴다 |
| ACC-3 | 기기 간 동기화: 한 기기에서 저장·변경한 것이 같은 계정의 다른 기기에 나타난다 |

**출시 범위 미정 (D-06)**

| ID | 요구사항 |
| --- | --- |
| ACC-4 | 데이터를 내보낸다 |
| ACC-5 | 계정과 데이터를 삭제한다 |

원문 §5.6 설정과 §11.8 대응에는 있으나 §6 P0 표에는 없다. 임의로 P0·P1 어느 쪽으로도 확정하지 않는다.

## 3. 플랫폼별 역할

| 플랫폼 | 역할 |
| --- | --- |
| 서버 | 사용자 식별, 세션 발급·검증, 사용자별 접근 제한 |
| 웹 | 회원가입·로그인 화면, 설정의 계정 항목 |
| 확장 | 로그인 상태 확인, 토큰 보관(`chrome.storage`) |
| 모바일 | 로그인 화면, 토큰 보관(`SecureStore`), 공유 확장과 세션 공유(iOS App Group, Android 공유 저장소) |

## 4. 동작 규칙

- 모든 콘텐츠는 비공개 기본값이고 소유 사용자만 접근한다.
- 공유 확장은 메인 앱의 로그인 세션을 그대로 쓴다. 공유창에서 다시 로그인하게 하지 않는다.

## 5. 완료 조건

D-08이 정해져야 쓸 수 있다. 정해진 뒤 여기에 검증 가능한 조건으로 적는다. 결정과 무관하게 성립해야 하는 것만 먼저 적는다.

- [ ] 로그인하지 않은 요청은 콘텐츠 API에서 401 `UNAUTHORIZED`를 받는다.
- [ ] 사용자 A의 토큰으로 사용자 B의 콘텐츠를 조회·수정·삭제할 수 없다.
- [ ] 한 기기에서 저장한 콘텐츠가 같은 계정의 다른 클라이언트 목록에 나타난다.
- [ ] iOS·Android 공유 확장이 메인 앱의 로그인 상태로 저장한다.

## 6. 의존

모든 기능이 이 문서에 의존한다. 스캐폴드에는 `users` 테이블과 토큰을 검증하지 않는 `requireAuth` 껍데기만 있다.

## 7. 미결정

- **D-08** 로그인 수단(이메일·비밀번호, 소셜, 매직 링크 등), 세션 방식과 만료, 확장의 로그인 방식(웹 세션 재사용 여부), "동기화"의 반영 시점(다음 조회 시 / 실시간), 인증을 직접 구현할지 외부 서비스를 쓸지
- **D-06** 내보내기·삭제의 출시 범위, 내보내기 형식
