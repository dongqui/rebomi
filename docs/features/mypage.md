# 마이페이지와 문의 (mypage)

원본: PRD v0.5 §5.6(설정) · 2026-11-25 사용자 결정으로 추가 · 의존: [account](account.md), [billing](billing.md)

> 원문 §5.6은 "설정"의 항목만 나열했고 화면이 속할 문서가 없었다. 2026-11-25에 사용자가 마이페이지를 만들기로 하면서 이 문서를 만들었다. 이름 표시·수정과 문의는 원문에 없던 요구사항이다.

## 1. 목적

사용자가 자기 계정이 무엇인지(이름, 이메일, 요금제) 확인하고, 문제가 있을 때 서비스에 문의할 수 있게 한다. 계정과 서비스 전체에 걸친 설정이 모이는 자리다.

## 2. 범위

**포함**

| ID | 요구사항 |
| --- | --- |
| MY-1 | 마이페이지가 있다. 원문의 "설정" 화면을 대신한다 — 설정 화면을 따로 두지 않는다. 웹과 모바일 모두에 있다 |
| MY-2 | 이름을 보여준다. 이름은 처음 가입할 때 Google·Apple이 준 이름이다 |
| MY-3 | 이름을 고친다 |
| MY-4 | 로그인한 계정의 이메일을 보여준다. 고칠 수 없다 |
| MY-5 | 요금제 이름(Free / Pro)을 보여준다 |
| MY-6 | 마이페이지 안의 문의 폼으로 문의를 보낸다 |
| MY-7 | 로그아웃한다 ([account ACC-8](account.md)의 진입점) |

**우선순위** — 원문 §6 P0 표에는 없다. **[제안]** P0로 본다: P0인 요금제 확인(BILL-4)과 재노출 설정(RES-6)이 놓일 화면이기 때문이다. `product.md` §6의 표(원문 그대로)는 고치지 않았다.

**제외 — 다른 문서의 요구사항이고, 그 기능을 만들 때 이 화면에 붙인다**

- 재노출 주기·대상, 푸시 설정 — [resurfacing RES-3, RES-6~7](resurfacing.md)
- 북마크 가져오기 진입점 — [import](import.md)
- 이번 달 사용량, 결제·업그레이드·해지 — [billing BILL-4](billing.md) (D-10). 2026-11-25: 지금 마이페이지에는 요금제 이름만 둔다
- 데이터 내보내기, 계정 삭제 — [account ACC-4~5](account.md) (D-06)

**제외 — 만들지 않는다**

- 이메일 변경, 프로필 사진
- 로그인 수단 연결·분리 ([account §2](account.md) 제외 항목)
- 도움말·FAQ 페이지, 실시간 상담

## 3. 플랫폼별 역할

| 플랫폼 | 역할 |
| --- | --- |
| 서버 | 내 계정 정보(이름, 이메일, 요금제) 조회, 이름 수정, 가입 시 제공자 이름 저장, 문의 접수 |
| 웹 | 마이페이지 화면. 지금 설정 자리에 있는 메뉴(테마·로그아웃)를 이 화면으로 잇는다 |
| 모바일 | 마이페이지 화면 |
| 확장 | 없음 |

화면의 모양은 디자인을 따른다. 2026-11-25 현재 디자인에 마이페이지가 없다(작업 중) — 화면 Issue는 디자인이 올라온 뒤에 실행한다.

## 4. 사용자 흐름

1. 마이페이지를 연다. 이름, 이메일, 요금제 이름이 보인다.
2. 이름을 고치면 저장되고, 다른 기기에서도 바뀐 이름이 보인다.
3. 문의 폼에 내용을 써서 보낸다. 보냈다는 확인이 보인다.
4. 로그아웃한다.

## 5. 동작 규칙과 예외

**결정된 것 (2026-11-25)**

- 마이페이지가 설정을 대신한다. 화면은 하나다.
- 이름은 제공자가 준 이름으로 시작하고 사용자가 고칠 수 있다.
- 구독 정보는 요금제 이름만 보여준다.
- 고객센터는 마이페이지 안의 문의 폼이다.

**이름**

- 제공자가 이름을 주지 않았으면(Apple은 처음 한 번만 주고, 주지 않을 수도 있다) 이름은 비어 있다. 이 문서를 만들기 전에 가입한 계정도 비어 있다. **[제안]** 비어 있으면 이메일의 `@` 앞부분을 이름 자리에 보여준다.
- **[제안]** 제공자의 이름은 계정을 만들 때 한 번만 저장한다. 그 뒤의 로그인은 이름을 덮어쓰지 않는다 — 사용자가 고친 이름이 로그인할 때마다 되돌아가면 안 된다.
- **[제안]** 이름은 앞뒤 공백을 떼고 1~50자다. 빈 이름으로는 저장되지 않는다.
- 이름은 다른 사용자에게 보이지 않는다(모든 콘텐츠가 비공개다). 계정을 묶는 기준도 아니다 — 그 기준은 이메일이다([account ACC-7](account.md)).

**요금제**

- 결제가 생기기 전에는 모든 계정이 Free다. 요금제의 뜻과 한도는 [billing](billing.md)에 있다.

**문의**

- 로그인한 사용자만 보낸다. 문의에는 보낸 계정이 함께 남는다 — 이메일을 다시 적게 하지 않는다.
- **[제안]** 내용은 앞뒤 공백을 떼고 1~2000자다. 첨부 파일은 없다.
- **[제안]** 보낸 뒤에는 내용을 지우고 보냈다는 확인을 보여준다. 실패하면 쓴 내용을 지우지 않는다.
- **[제안]** 문의에는 보낸 클라이언트(웹 / iOS / Android)와 앱 버전이 함께 남는다 — 문제를 재현할 때 필요하다.
- 문의를 운영자가 어떻게 받고 답하는지는 D-20, 보관 기간은 D-21.

## 6. 완료 조건

- [ ] 웹과 모바일에 마이페이지가 있고, 로그인한 사용자만 볼 수 있다.
- [ ] Google 또는 Apple로 처음 가입하면 제공자가 준 이름이 마이페이지에 보인다.
- [ ] 이름이 없는 계정은 이메일의 앞부분이 이름 자리에 보인다.
- [ ] 이름을 고치면 저장되고, 같은 계정의 다른 클라이언트에서 바뀐 이름이 보인다.
- [ ] 이름을 고친 뒤 다시 로그인해도 고친 이름이 그대로다.
- [ ] 빈 이름과 50자를 넘는 이름은 저장되지 않고 이유가 보인다.
- [ ] 로그인한 계정의 이메일이 보이고 고칠 수 없다.
- [ ] 요금제 이름이 보인다.
- [ ] 문의를 보내면 D-20에 정한 대로 운영자에게 닿고, 사용자에게 보냈다는 확인이 보인다.
- [ ] 빈 문의와 2000자를 넘는 문의는 보내지지 않는다.
- [ ] 로그인하지 않은 요청은 내 계정 정보 조회·이름 수정·문의 접수에서 401 `UNAUTHORIZED`를 받는다.
- [ ] 사용자 A의 토큰으로 사용자 B의 이름을 보거나 고칠 수 없다.
- [ ] 마이페이지에서 로그아웃할 수 있다.

## 7. 의존

- [account](account.md) — 로그인, 계정, 로그아웃. 제공자에게서 이름을 받으려면 로그인 흐름이 바뀐다(Google은 이름 범위를 요청해야 하고, Apple은 이름을 신원 토큰이 아니라 첫 로그인의 응답으로만 준다). 기술적인 내용은 구현할 때 [architecture §3](../architecture.md#3-인증과-기기-동기화)에 적는다
- [billing](billing.md) — 요금제

## 8. 미결정

- **D-20** 문의를 운영자가 받고 답하는 방법
- **D-21** 문의의 보관 기간과 삭제
- `[제안]`으로 표시한 것: 우선순위(P0), 이름이 없을 때의 표시, 이름의 길이 제한, 제공자 이름을 한 번만 저장하는 것, 문의의 길이 제한과 함께 남기는 정보
