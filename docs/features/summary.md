# 자동 요약 (summary)

원본: PRD v0.5 §4.2, §8(서버), §9(비용 통제), §13 H3 · 공통 규칙: [architecture §4 상태](../architecture.md#4-콘텐츠의-공통-상태), [§7 비용 통제](../architecture.md#7-비용-통제와-사용량-집행)

## 1. 목적

원문을 열지 않고도 콘텐츠의 주제와 유용성을 판단해 보관할지 버릴지 바로 결정하게 한다. AI는 원본을 이해하는 일을 돕되 원본을 대체하지 않는다.

## 2. 범위

**P0 포함**

| ID | 요구사항 |
| --- | --- |
| SUM-1 | 추출된 본문을 바탕으로 1~3문장 요약을 만든다 |
| SUM-2 | 사용자 언어에 맞게 요약한다 (한국어·영어) |
| SUM-3 | 요약 상태를 구분해 보여준다: 생성 중 / 완료 / 실패 / 본문 없음 |
| SUM-4 | 메타데이터만 있는 콘텐츠는 OG 설명을 요약 자리에 표시한다 |
| SUM-5 | 요약과 함께 원본 제목, 출처, 이미지를 표시한다 |
| SUM-6 | (비용 통제, §9) 본문 입력 토큰에 상한을 둔다(예: 4,000). 링크 소멸 콘텐츠는 요약하지 않는다. 동일 URL의 요약·임베딩은 공개 페이지에 한해 사용자 간 캐시를 공유한다 |

**제외 (P1)**

핵심 포인트 추출, 요약 재생성, 여러 요약 길이, YouTube 자막 기반 상세 요약.

## 3. 플랫폼별 역할

| 플랫폼 | 역할 |
| --- | --- |
| 워커 | 요약 잡 실행, 재시도, 한도·토큰 상한 집행, 캐시 |
| 서버 | 요약과 상태를 콘텐츠 응답에 포함 |
| 웹·모바일 | 요약과 상태 표시 |
| 확장 | 없음 (저장 직후에는 요약이 아직 없다) |

## 4. 사용자 흐름

1. 콘텐츠가 저장되면 "생성 중"으로 보인다.
2. 워커가 본문으로 요약을 만들면 "완료"로 바뀌고 요약이 표시된다.
3. 본문이 없으면 "본문 없음"이고 OG 설명이 요약 자리에 나온다.
4. 실패하면 "실패"로 보인다(재시도 소진 후).

## 5. 동작 규칙과 예외

- 요약은 저장 응답을 막지 않는다. 요약이 없어도 콘텐츠는 목록과 키워드 검색에 나타난다.
- 실패는 자동 재시도한다. 사용자가 누르는 "재생성"은 P1이다.
- 월 AI 한도를 넘으면 요약하지 않고 메타데이터만 유지한다. 이때 사용자에게 어떤 상태로 보일지는 D-03.
- 요약이 임베딩의 입력으로도 쓰인다(검색 대상에 요약 포함). → [search](search.md)

## 6. 완료 조건

- [ ] 본문이 있는 콘텐츠는 저장 후 요약이 1~3문장으로 표시된다.
- [ ] 요약 전·중·후·실패·본문 없음이 화면에서 서로 구분된다.
- [ ] 메타데이터만 있는 콘텐츠는 OG 설명이 요약 자리에 나오고, LLM 호출이 일어나지 않는다.
- [ ] 한국어 본문과 영어 본문 각각에 대해 SUM-2의 기준(D-13)대로 요약 언어가 정해진다.
- [ ] 토큰 상한을 넘는 본문은 잘려서 입력되고 요약이 실패하지 않는다.
- [ ] 링크 소멸 콘텐츠에는 요약 잡이 실행되지 않는다.
- [ ] 일시적 LLM 오류는 재시도되고, 소진되면 "실패"로 표시된다.
- [ ] 요약 1건당 비용이 측정·기록된다 (Phase 2 게이트).
- [ ] 계측: 요약만 보고(원문을 열지 않고) 보관·삭제한 행동을 구분할 수 있다 (H3).
